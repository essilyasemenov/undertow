# HTTPS

## 1. Что это такое

`HTTPS` — зашифрованная версия `HTTP`, которая использует `TLS` для защиты связи между клиентом и сервером. MDN определяет HTTPS как защищённое HTTP-соединение для обмена чувствительными данными.

## 2. Зачем это нужно

- защищать логины, токены, cookies и трафик панели и API;
- не допускать подмены содержимого по пути;
- обеспечивать браузеру защищённый контекст (`secure context`);
- снижать риск `MITM` и снятия шифрования (SSL stripping).

## 3. Как это связано с VPN-инфраструктурой

- панели, dashboard, страницы подписок и административные интерфейсы почти всегда доступны через веб;
- даже если VPN-транспорт не HTTP, управление обычно идёт через браузер и API;
- незашифрованный HTTP для административного или публичного веб-слоя создаёт лишний риск утечки и подмены.

## 4. Как это связано с Cloudflare

- Cloudflare часто выступает точкой входа HTTPS перед origin;
- при публикации через Cloudflare нужно понимать цепочку редиректов и разделение на участки edge и origin;
- сертификат на edge сам по себе не делает защищённым участок до origin.

## 5. Как это связано с Remnawave

- панель, API и страница подписок `Remnawave` доступны через веб;
- reverse proxy (Caddy, Nginx, `Nginx Proxy Manager` и другие) отвечает за практическую публикацию backend-сервисов по HTTPS.

## 6. Типовые ошибки

- оставлять панель на HTTP без шифрования;
- настраивать редирект, не понимая HSTS и риска первого запроса по HTTP;
- забывать про смешанное содержимое (mixed content);
- путать «HTTPS на edge» и «защищённый origin»;
- публиковать backend по HTTPS, но не закрывать прямой доступ к нему.

## 7. Диагностика

1. Проверить, что происходит при запросе `http://`.
2. Проверить, открывается ли адрес `https://`.
3. Проверить срок действия сертификата и совпадение имени.
4. Проверить смешанное содержимое и цепочку редиректов.
5. Проверить цепочку `DNS -> TCP/443 -> TLS -> ответ HTTP`.

## 8. Практические примеры

- Перевод домена Remnawave Panel с HTTP на HTTPS за reverse proxy.
- Публикация страницы подписок `Remnawave` по HTTPS за Cloudflare.
- Разбор смешанного содержимого после перевода панели на HTTPS.
- Сравнение прямого доступа к origin и доступа через цепочку CDN / прокси.

## 9. Чек-лист

- Выяснить, что именно публикуется: панель, API, dashboard или страница подписок.
- Проверить редирект с HTTP на HTTPS.
- Проверить, нет ли смешанного содержимого и ресурсов, загружаемых по HTTP.
- Разделить проблемы TLS, DNS, reverse proxy и firewall.
- При необходимости перейти к `tls.md` и `reverse-proxy.md`.
