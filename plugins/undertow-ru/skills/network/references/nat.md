# NAT

Использовать этот раздел, когда нужно объяснить, почему внутренний адрес не виден в Интернете, как работает выход в Интернет из частной сети и почему входящие подключения не доходят без дополнительной настройки.

## Простое объяснение

NAT переводит один IP-адрес в другой. Чаще всего домашний роутер заменяет частный IPv4-адрес клиента на один публичный адрес на WAN.

## Техническое объяснение

Традиционный NAT описан в RFC 3022. На практике чаще встречается NAPT/PAT: трансляция не только адреса, но и транспортного порта, чтобы множество внутренних хостов могли разделять один внешний IPv4-адрес.

## История

- Массовое внедрение NAT связано с дефицитом IPv4-адресов.
- RFC 1918 закрепил частные диапазоны IPv4.
- RFC 3022 описывает traditional NAT и operational ограничения.

## Компоненты

- private IPv4
- public IPv4
- translation table
- state timeout
- source NAT
- destination NAT
- PAT/NAPT

## Типичные ошибки

- "NAT = firewall" - нет, это разные функции, хотя часто реализуются вместе.
- "Проброс порта всегда решает проблему" - нет, если есть второй NAT, CGNAT или сломан route back.
- "IPv6 тоже всегда требует NAT" - как правило, нет.

## NAT и PAT: подробно

### RFC и нормативная база

- RFC 1918 - private IPv4
- RFC 2663 - NAT terminology
- RFC 3022 - Traditional NAT
- RFC 4787 - NAT behavioral requirements for UDP
- RFC 5382 - NAT behavioral requirements for TCP

### Ключевые формы NAT

| Термин | Что меняется | Типичный кейс |
| --- | --- | --- |
| SNAT | Source address | Выход LAN в Интернет |
| DNAT | Destination address | Публикация внутреннего сервиса |
| PAT/NAPT | Source/destination port + address | Много клиентов за одним IPv4 |

### ASCII-схема PAT

```text
192.168.1.10:51514
  -> router NAT
203.0.113.5:40001
  -> 93.184.216.34:443

reply:
93.184.216.34:443
  -> 203.0.113.5:40001
  -> router translates back
  -> 192.168.1.10:51514
```

### ASCII-схема DNAT

```text
internet client -> 203.0.113.5:443
  -> DNAT on edge router
  -> 192.168.1.20:443
```

### Linux-команды

```sh
ip addr
ip route
ss -lntup
tcpdump -ni any host <public-ip>
nft list ruleset
conntrack -L
```

### Практические примеры диагностики

#### Исходящее соединение работает, входящее нет

Проверять:

1. есть ли DNAT;
2. разрешает ли firewall трафик в цепочках forward и input;
3. слушает ли сервис нужный адрес/порт;
4. правильный ли путь возврата.

#### Hairpin NAT

Клиент из LAN обращается к сервису по публичному адресу. Если reflection не настроен, извне сервис работает, а изнутри по публичному IP - нет.

### Реальные сетевые сценарии

#### Сценарий 1. Домашний роутер публикует NAS

Нужны одновременно:

- публичный IPv4;
- DNAT;
- разрешающий firewall;
- сервис, слушающий нужный адрес;
- корректный route back.

#### Сценарий 2. Корпоративный outbound через SNAT

Внутренние серверы выходят наружу под общим адресом firewall, и внешняя система видит не реальные хосты, а адрес границы.

### Типичные ошибки на практике

- Считать NAT и firewall одним и тем же.
- Забывать про обратный маршрут.
- Путать DNAT публикации и SNAT выхода.
- Искать причину только на сервере, игнорируя границу NAT.

### Порядок диагностики

1. Определить, где именно выполняется NAT.
2. Сопоставить частный и публичный адрес и порт.
3. Проверить правила SNAT/DNAT.
4. Проверить conntrack/state.
5. Проверить маршрут возврата и bind/listen приложения.

| Термин | Определение | Назначение | Принцип работы | Преимущества | Недостатки/ограничения | Практический пример | Реальный сценарий | Связь |
| --- | --- | --- | --- | --- | --- | --- |
| NAT | Трансляция адресов | Совместить разные адресные пространства | Пакет проходит через устройство, которое меняет IP-поля и хранит состояние | Экономит IPv4 | Нарушает end-to-end | Домашний роутер | LAN выходит в Интернет через один WAN IP | Связан с IPv4 |

## Примеры

### Пример 1. Домашняя сеть

Десять устройств с адресами `192.168.1.0/24` выходят в Интернет через один публичный адрес провайдера. На границе выполняется PAT.

### Пример 2. Публикация веб-сервера

```text
203.0.113.5:443
  -> DNAT
192.168.1.20:443
```

Чтобы это работало, нужны:

- корректный DNAT;
- разрешение входящего трафика firewall;
- маршрут возврата через тот же маршрутизатор.

### Частые вопросы

#### Почему с мобильного Интернета нельзя открыть мой домашний сервис?

Возможные причины: нет проброса порта, двойной NAT, CGNAT, firewall drop, сервис слушает не тот адрес.
