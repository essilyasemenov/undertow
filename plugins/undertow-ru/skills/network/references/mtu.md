# MTU

Использовать этот раздел, когда есть симптомы вида "часть сайтов открывается, часть зависает", "через VPN медленно", "QUIC работает, а TCP ломается" или "большие пакеты пропадают".

## Простое объяснение

MTU - максимальный размер IP-пакета, который можно передать по конкретному каналу без фрагментации. MSS - максимальный размер полезных TCP-данных внутри сегмента.

## Техническое объяснение

MTU привязан к каналу или логическому интерфейсу. Для IPv4 возможна фрагментация маршрутизаторами, хотя практически это нежелательно. Для IPv6 маршрутизаторы не фрагментируют транзитные пакеты; критична корректная работа PMTUD по RFC 8201 и ICMPv6.

## История

- Классическая PMTUD для IPv4 описана в RFC 1191.
- IPv6 PMTUD описана в RFC 8201.
- MSS исторически связан с RFC 879 и развитием TCP.

## Компоненты

- MTU интерфейса
- IP fragmentation
- DF bit в IPv4
- ICMP Fragmentation Needed / Packet Too Big
- PMTUD
- TCP MSS

## Типичные заблуждения

- "Если уменьшить MTU, всегда станет лучше" - не всегда; можно потерять throughput.
- "MSS и MTU одно и то же" - нет, MSS меньше MTU, так как TCP/IP заголовки занимают место.
- "ICMP можно смело полностью блокировать" - это часто ломает PMTUD, особенно в IPv6.

## MTU, MSS и PMTUD: подробно

### RFC и нормативная база

- RFC 879 - TCP MSS
- RFC 1191 - Path MTU Discovery for IPv4
- RFC 4821 - Packetization Layer Path MTU Discovery
- RFC 8201 - Path MTU Discovery for IPv6

### Базовая логика

| Термин | Смысл |
| --- | --- |
| MTU | Максимальный размер IP-пакета на интерфейсе/канале |
| MSS | Максимальный размер полезной нагрузки TCP |
| PMTU | Наименьший MTU по пути |
| PMTUD | Механизм обнаружения PMTU |

### ASCII-схема

```text
host A MTU 1500
  -> router
  -> tunnel segment effective MTU 1420
  -> router sends ICMP too big / fragmentation needed
  -> host reduces packet size or MSS
```

### Практические вычисления

```text
Ethernet MTU 1500
IPv4 + TCP: MSS 1460
IPv6 + TCP: MSS 1440
```

### Linux-команды

```sh
ip link show
tracepath 1.1.1.1
tracepath6 2606:4700:4700::1111
ping -M do -s 1472 1.1.1.1
ping6 -s 1440 2606:4700:4700::1111
tcpdump -ni any 'icmp or icmp6'
```

### Практические примеры диагностики

#### Проверка black hole MTU

```sh
ping -M do -s 1472 8.8.8.8
ping -M do -s 1400 8.8.8.8
```

Если большой пакет не проходит, а меньший проходит, по пути есть более узкий MTU или сломан PMTUD.

#### Проверка TCP MSS косвенно

Снять `tcpdump` на SYN и посмотреть negotiated MSS.

### Реальные сетевые сценарии

#### Сценарий 1. PPPoE + VPN

Наружный канал уже уменьшает доступный payload, а поверх него добавляется overhead туннеля. Без корректного MTU/MSS часть сайтов зависает на TLS или загрузке крупных объектов.

#### Сценарий 2. IPv6 работает хуже IPv4

Часто причина не в "плохом IPv6", а в фильтрации ICMPv6 `Packet Too Big`.

### Типичные ошибки

- Полностью блокировать ICMP/ICMPv6.
- Путать MTU и MSS.
- Изменять MTU на клиенте, не проверив bottleneck по пути.
- Игнорировать overhead PPPoE, GRE, VXLAN, WireGuard, OpenVPN, IPsec.

### Порядок диагностики

1. Проверить MTU интерфейсов.
2. Проверить реальный PMTU через `tracepath`.
3. Проверить ICMP/ICMPv6 сообщения `too big`.
4. Сравнить поведение малых и больших пакетов.
5. Для TCP оценить negotiated MSS и возможный MSS clamp.

## Примеры

### Пример 1. PPPoE

Если поверх Ethernet используется PPPoE, доступный payload уменьшается. Типовой MTU становится меньше 1500, и без учета этого возможны подвисания некоторых TCP-сессий.

### Пример 2. WireGuard через домашний роутер

Наружный интерфейс имеет MTU 1500, но поверх него идет туннель с дополнительными заголовками. Эффективный путь меньше 1500. Если не настроить корректный MTU/MSS, часть трафика будет идти с потерями.

### Пример 3. Проверка большого ping

```sh
ping -M do -s 1472 8.8.8.8
tracepath 8.8.8.8
```

Если `ping` с `-M do` не проходит, а меньший размер проходит, по пути есть меньший MTU или блокировка ICMP.

### Реальный сценарий использования

После включения туннеля пользователь жалуется: "открываются только простые сайты". Часто это не DNS, а именно MTU/PMTUD black hole.
