# Gateway

Использовать этот раздел, когда нужно объяснить, как хост выходит за пределы своей подсети и почему неверный default gateway ломает Интернет даже при корректном IP-адресе.

## Простое объяснение

Шлюз по умолчанию - это адрес маршрутизатора, которому хост отправляет пакеты для всех сетей, не находящихся в его собственной подсети.

## Техническое объяснение

Хост сначала определяет, входит ли IP-адрес назначения в его локальный префикс. Если да, он находит MAC-адрес соседа и отправляет кадр напрямую. Если нет, он использует маршрут по умолчанию (default route) и отправляет кадр на MAC-адрес шлюза.

## История

- Понятие gateway исторически тесно связано с ранней IP-маршрутизацией.
- В учебных материалах Cisco маршрут по умолчанию и шлюз последней надежды (gateway of last resort) — базовые элементы практики.

## Default Gateway: подробно

### RFC и нормативная база

- RFC 1122 - Host Requirements
- RFC 1812 - Router Requirements
- RFC 4861 - Neighbor Discovery for IPv6

### Базовый принцип

Хост сам не знает все сети мира. Для не-локальных адресов он отправляет пакет на default gateway.

### ASCII-схема

```text
host 192.168.1.10/24
  -> destination 8.8.8.8 not local
  -> send frame to gateway 192.168.1.1 MAC
  -> router forwards further
```

### Отличия терминов

| Термин | Значение |
| --- | --- |
| Default gateway | Шлюз хоста для не-локальных сетей |
| Next hop | Следующий узел в конкретном маршруте |
| Default route | Маршрут `0.0.0.0/0` или `::/0` |

### Linux-команды

```sh
ip addr
ip route
ip route get 8.8.8.8
arp -an
ip neigh
ping -c 3 <gateway-ip>
```

### Практические примеры диагностики

#### Неверный gateway от DHCP

```sh
ip route
ping -c 3 <gateway-ip>
```

Если gateway находится вне подсети хоста, трафик за пределы LAN не выйдет.

#### IPv6 default route не получен

Проверить Router Advertisement, `ip -6 route`, `ip -6 neigh`.

### Реальные сетевые сценарии

#### Сценарий 1. Домашний клиент видит соседей, но не Интернет

Обычно локальный L2 исправен, а default gateway не получен, неверен или недоступен.

#### Сценарий 2. Сервер с двумя интерфейсами

Неправильный default route уводит ответы не тем интерфейсом, и соединение выглядит "плавающим".

### Типичные ошибки

- Ставить gateway не из своей подсети IPv4.
- Считать, что успешный `ping` до соседа проверяет маршрут по умолчанию.
- Игнорировать отдельную проверку IPv6 default route.

### Порядок диагностики

1. Проверить адрес и префикс интерфейса.
2. Проверить default route.
3. Проверить ARP/NDP до gateway.
4. Проверить, что сам gateway имеет путь дальше.
5. Для multi-homed систем проверить policy routing.

## Глоссарий

| Термин | Определение | Назначение | Принцип работы | Преимущества | Недостатки/ограничения | Практический пример | Реальный сценарий | Связь |
| --- | --- | --- | --- | --- | --- | --- |
| Default gateway | Маршрутизатор для неизвестных сетей | Дать хосту выход за пределы подсети | Хост отправляет не-локальный трафик на адрес шлюза | Простая модель | Один неверный адрес ломает reachability | `192.168.1.1` на домашнем ПК | Клиент выходит в Интернет через домашний роутер | Связан с routing |
| Gateway of last resort | Аналог default route на маршрутизаторе | Доставлять трафик к неизвестным сетям | Используется, когда нет более специфичного маршрута | Универсальность | Может стать черной дырой | `0.0.0.0/0 via ...` | Пограничный роутер отправляет трафик провайдеру | Частный случай маршрута |
| ARP/NDP до gateway | Поиск L2-адреса шлюза | Передать кадр на router | Хост сначала узнает MAC/L2-идентификатор шлюза | Делает L3 достижимым через L2 | Ломается при VLAN/L2 проблемах | MAC шлюза в ARP-cache | Клиент не может выйти в Интернет из-за сбоя ARP | Связь L2 и L3 |

## Примеры

### Пример 1. Неверный gateway от DHCP

Клиент получил `192.168.1.50/24`, но gateway `192.168.2.1`. Локальные хосты работают, Интернет не работает.

### Пример 2. Доступ к локальному серверу без gateway

Если сервер и клиент находятся в одной подсети, они могут общаться напрямую без участия gateway.

### Частый вопрос

#### Почему я пингую соседний адрес, хотя gateway сломан?

Потому что для той же подсети трафик идет напрямую, не через default gateway.
