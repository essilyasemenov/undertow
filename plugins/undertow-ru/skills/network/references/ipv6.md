# IPv6

Использовать этот раздел, когда нужно объяснить современную адресацию Интернета, dual-stack, глобальные адреса, SLAAC, link-local и роль ICMPv6.

## Простое объяснение

IPv6 - это новая версия IP с гораздо большим адресным пространством. Она создана не только ради большего числа адресов, но и ради более современной модели доставки.

## Техническое объяснение

IPv6 определен RFC 8200. Адрес состоит из 128 бит. IPv6 массово использует prefix-based routing, соседское взаимодействие через NDP, автоматическую адресацию SLAAC и критически зависит от ICMPv6 для корректной работы многих механизмов, включая PMTUD.

## История

- Создан как ответ на ограничения IPv4.
- RFC 8200 заменил более раннюю спецификацию RFC 2460.
- В отличие от IPv4, IPv6 изначально проектировался под огромную адресную емкость и более строгую модель фрагментации.

## IPv6: подробно

### RFC и нормативная база

- RFC 4291 - IPv6 Addressing Architecture
- RFC 4443 - ICMPv6
- RFC 4861 - Neighbor Discovery for IPv6
- RFC 4862 - Stateless Address Autoconfiguration
- RFC 4193 - Unique Local IPv6 Unicast Addresses
- RFC 8200 - IPv6
- RFC 8201 - PMTUD for IPv6
- RFC 8504 - IPv6 Node Requirements

### Типы адресов

| Тип | Пример | Назначение |
| --- | --- | --- |
| Global Unicast | `2001:db8::1` | Глобальная маршрутизация |
| Link-local | `fe80::1` | Служебная локальная связность |
| Unique Local (ULA) | `fc00::/7`; на практике `fd00::/8` (локально назначаемые префиксы) | Локальная маршрутизация |
| Multicast | `ff02::1` | Групповая доставка |

### ASCII-схема

```text
host
  -> receives RA
  -> builds SLAAC address
  -> learns default router via link-local
  -> sends traffic using IPv6 routing
```

### Linux-команды

```sh
ip -6 addr
ip -6 route
ip -6 neigh
ping6 2606:4700:4700::1111
traceroute6 2606:4700:4700::1111
tcpdump -ni any 'icmp6'
```

### Практические примеры диагностики

#### Проверка Router Advertisement и default route

Проверить наличие глобального адреса, link-local next hop и маршрута `::/0`.

#### Проверка ICMPv6 `Packet Too Big`

Если часть соединений зависает, нужно искать фильтрацию критичных ICMPv6 сообщений.

### Реальные сетевые сценарии

#### Сценарий 1. Dual-stack с broken IPv6

Если клиент предпочитает AAAA и IPv6-path частично сломан, пользователь видит "сайт долго думает", хотя IPv4-path здоров.

#### Сценарий 2. Домашний провайдер выдает /56

Роутер может раздать разные /64 по VLAN или LAN-сегментам без NAT66.

### Типичные ошибки

- Блокировать ICMPv6 как "лишний шум".
- Пытаться мыслить broadcast-моделью IPv4.
- Считать NAT обязательной частью IPv6.
- Игнорировать link-local адреса как служебные и неважные.

### Порядок диагностики

1. Проверить наличие GUA/ULA/link-local адресов.
2. Проверить `::/0` и next hop.
3. Проверить NDP и ICMPv6.
4. Проверить MTU/PMTUD.
5. Сравнить IPv4 и IPv6 пути отдельно.

## Примеры

### Пример 1. Dual-stack

Хост имеет одновременно:

- IPv4: `192.0.2.10`
- IPv6: `2001:db8:1::10`

Сервис может предпочитать IPv6, если есть AAAA-запись и путь доступен.

### Пример 2. Link-local gateway

В IPv6 next hop часто представлен link-local адресом маршрутизатора, а не глобальным адресом.

### Пример 3. Поломка из-за ICMPv6

Если firewall режет `Packet Too Big` и другие нужные ICMPv6, некоторые соединения будут деградировать или зависать, несмотря на наличие адресов и маршрутов.
