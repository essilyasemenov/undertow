# Cloudflare Zero Trust

Доступ к приложению или частному ресурсу не «по открытому URL для всех», а по модели, где решение принимают identity и политики.

## Базовая модель

- `Cloudflare Access` через Access policies определяет, кто может получить доступ к приложению.
- `Identity Provider` (IdP) — источник identity пользователей.
- `Cloudflare One Client` (бывший WARP) подключает устройство к сети Cloudflare и передаёт политикам данные об устройстве.
- `Service Tokens` нужны для доступа сервис–сервис и автоматизации.
- Сетевой путь до частного ресурса или локального сервиса обычно задаётся через Tunnel ([tunnel.md](tunnel.md)); этот раздел не заменяет Tunnel и не описывает публикацию на уровне коннектора.

## Что проектировать

- Кто получает доступ: пользователь, группа, сервис, устройство.
- Что защищается: Access application, точка для автоматизации или другой частный ресурс.
- Что требуется для входа: логин через IdP, mTLS, service token или проверка устройства через Cloudflare One Client (device posture).

## Рабочий процесс

1. Определить ресурс и способ доступа: браузерное приложение, частное имя, частный IP/CIDR, автоматизация.
2. Выбрать тип Access application и модель политик.
3. Подключить IdP, если доступ выдаётся пользователям.
4. Если доступ зависит от устройства, решить, нужен ли Cloudflare One Client.
5. Для автоматизации решить, подходит ли service token.
6. Если модель приложения этого требует, проверять токен Access и на стороне origin.

## Практические правила

- Для внутренней панели, домашней панели или административного интерфейса сначала рассматривать Access, а не публичный URL без аутентификации.
- Для доступа к частной сети учитывать по отдельности сетевой путь, слой identity и клиентский путь через Cloudflare One Client.
- Для партнёров, подрядчиков и нескольких доменов identity учитывать, что Cloudflare поддерживает несколько IdP одновременно.
- Для сервисов без интерактивного входа рассматривать `Service Auth` и `Service Tokens`.

## Что не делать

- Не считать Zero Trust просто «ещё одним VPN».
- Не путать public hostname через Tunnel и частный доступ через Cloudflare One Client: для пользователя это разные сценарии.
- Не выдавать service token за аналог пользовательской сессии.
- Не пропускать проверку токена на origin там, где её требует официальная документация.
