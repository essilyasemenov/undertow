# Cloudflare DNS

DNS-часть публикации через Cloudflare: записи, proxy status, DNSSEC.

## Базовые правила

- Архитектурная разница между `Proxied` и `DNS only` описана в [SKILL.md](../SKILL.md); этот раздел применяет её к конкретным DNS-записям.
- Проксировать можно только записи `A`, `AAAA` и `CNAME`; записи остальных типов всегда работают как `DNS only`.
- `MX`, `TXT`, `NS`, `SRV` и большинство служебных записей не описывать как проксируемый веб-трафик.
- `Proxied` нужен там, где трафик должен идти через edge Cloudflare.
- `DNS only` нужен там, где Cloudflare должна только отдавать DNS-ответ и не становиться reverse proxy.

## Как выбирать запись

- `A`: имя указывает на IPv4-адрес origin.
- `AAAA`: имя указывает на IPv6-адрес origin.
- `CNAME`: имя указывает на другое каноническое имя.
- `MX`: маршрутизация почты.
- `TXT`: верификация домена, SPF/DKIM/DMARC и другие текстовые данные.
- `NS`: делегирование поддомена или особые сценарии с авторитативными серверами.
- `SRV`: поиск сервиса по имени, порту и приоритету.

## Рабочий процесс

1. Определить, что стоит за именем: веб-ресурс, почтовый сервис, запись для верификации или маршрут к частному ресурсу.
2. Выбрать тип записи по её функции, а не по привычке.
3. Для `A` / `AAAA` / `CNAME` решить, нужен `Proxied` или `DNS only`.
4. Если домен нужно защитить от подмены DNS-ответов, проверить сценарий DNSSEC.
5. Если сервис зависит от прямого IP, нестандартного транспорта или сторонней проверки домена, отдельно проверить, допустим ли `DNS only`.

## Практические правила

- Для публичных HTTP(S)-имён сначала рассматривать `A`, `AAAA` или `CNAME` с `Proxied`.
- Для сторонней верификации домена и части SaaS-интеграций не включать проксирование без явного подтверждения в документации.
- `MX` описывать как почтовую запись, а не как точку входа Cloudflare CDN.
- `NS` для делегирования поддомена применять только там, где действительно нужна граница делегирования.
- Для DNSSEC опираться на текущую схему подключения зоны: full setup, subdomain setup или миграция.

## Проверка и диагностика

- Проверять тип записи, имя, содержимое, TTL и proxy status по отдельности.
- Не смешивать на одном имени вручную созданные HTTPS-записи с проксируемыми записями без проверки официальных ограничений.
- Если есть сомнение, поддерживает ли конкретная запись режим `Proxied`, ответ дают официальные ограничения Cloudflare DNS (раздел DNS в [sources.md](sources.md)).

## Что не делать

- Не называть `MX`, `TXT`, `SRV` или `NS` записями «под оранжевым облаком».
- Не обещать, что любой `CNAME` можно безопасно проксировать.
- Не придумывать шаги DNSSEC; использовать только описанную в документации последовательность.
