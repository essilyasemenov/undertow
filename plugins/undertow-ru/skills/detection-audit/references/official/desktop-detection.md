# Признаки на desktop и UNIX-платформах

Этот файл содержит только признаки этапа «Широта охвата», прямо описанные в методичке.

## macOS

В разделе `8.4. MacOS` указаны:

- перечисление интерфейсов, включая виртуальные, через `getifaddrs()`;
- анализ таблицы маршрутизации на нестандартную маршрутизацию;
- `Transparent Proxy API` как отдельный тип сетевого контура;
- системные расширения `Network Extensions`, требующие явного разрешения пользователя;
- принудительная маршрутизация `enforceRoutes` как дополнительный технический признак.

## UNIX и Linux

В разделе `8.5. UNIX и Linux` указаны:

- имена интерфейсов `tun`, `tap`, `wg`, `utun`, `ppp`;
- учитываются только активные интерфейсы в статусе `UP` с назначенным IP;
- MTU туннельных интерфейсов часто ниже стандартного, например `1350` или `1400`;
- несколько маршрутов по умолчанию, маршруты через виртуальные интерфейсы, нетипичные подсети и измененный DNS как дополнительная аналитика;
- `/etc/resolv.conf` и иные конфигурации DNS только как поддерживающий фактор;
- сравнение локального и публичного IP и принадлежность адреса ЦОД как дополнительные признаки.

## Windows

В разделе `8.6. Windows` указаны:

- `RasEnumConnection` для активных удаленных подключений;
- `GetAdaptersAddresses` или `GetAdaptersInfo` для анализа адаптеров;
- виртуальный тип адаптера `IfType = IF_TYPE_PROP_VIRTUAL`, названия VPN, TAP, Wintun, WireGuard, OpenVPN и состояние `UP`;
- анализ реестра на VPN- и proxy-настройки как расширенный метод;
- шлюз по умолчанию, DNS, расхождение публичного и локального IP, метрики интерфейсов как дополнительные факторы точности.

## Общее правило раздела 8

Интерфейсы, маршруты, MTU, частные подсети и DNS сами по себе не являются достаточным основанием для жесткого решения без серверного риска или иных сильных подтверждений.
